作者原话："我准备睡觉，你盯着子程序，叫他们持续跑就行，我不叫停就最好不要停下来，就是优化游戏，知道每一个细节都精致，从手感到关卡，从美术到bug"。

Jam 截止：2026-10-19 22:00 UTC。网页版必须一直能跑。

## 怎么干活
1. **不停**：做完一项，立刻做你清单里的下一项。清单做完了，自己在你负责的领域里找下一件最影响体验的事接着做。不用等作者，也不用等监督会话批准。
2. **一项一个闭环**：改 → 限时编译检查（0 个 SCRIPT ERROR / Parse Error）→ headless 验证 → 关键改动用网页版截图，存进 `截图/夜间打磨/<你的领域>/` → 用 SendMessage 给「监督新游戏」会话发一两句：改了什么、哪些文件、截图路径。
3. **别吵醒作者**：夜里不要用 SendUserFile，也不要发推送。截图只存文件，监督会话早上统一整理。
4. **大方向不改**：不删玩法，不改关卡结构、剧情、武器种类。这类想法写进你的报告，早上作者定。数值小步调，改了就写进 `策划案.txt`。

## 安全
- 不 commit，不 push。
- 跑 Godot（headless、录像、导出）一律加 `--log-file <你自己的 scratchpad>/xxx.log`，并且限时；看到第一个 SCRIPT ERROR 或 Parse Error 就中止。测试脚本不要逐帧 print。
- 每个会话同一时间最多开 1 个 Godot 进程。只 kill 自己开的进程，不碰作者的编辑器。
- **杀进程只能按自己记下的 PID**：启动时用 `$!` 记下 PID，超时看门狗只杀这个 PID。禁止用 `pkill`、`killall`、`pgrep -f Godot`、`pgrep -n`、`pgrep oscar-rush` 这类按名字找进程的写法，它们会误杀别的会话的测试。2026-10-18 凌晨就出过别人的测试几秒内被 kill -9（退出码 137）的事。
- **测试别碰作者的设置存档**：跑任何会读写设置的测试（菜单、设置、语言、像素完美、音量）时，一律加环境变量 `SCRAP_SETTINGS_PATH=<你自己的 scratchpad>/s.cfg`，这样就不会改到作者电脑上真正的 user://settings.cfg。
- 长测试前先 `df -h /` 看一眼，剩余空间小于 30 GB 就停下，告诉监督会话。
- 改完代码马上做一次限时编译检查，别把编译不过的工程留给别人。2026-10-17 就因为这个把日志刷到 20 GB。
- 只改自己领域的文件。必须改别人的文件时，先 SendMessage 打招呼，再看 `git diff`，只做最小改动，别盖掉别人的改动。
- 新加给玩家看的文字，同时加进 `oscar-rush/localization/text.csv`，中英文都要有。字体子集由中文模式会话负责更新。
- 发现别人领域的 bug：发给负责的会话，同时抄送监督会话。
